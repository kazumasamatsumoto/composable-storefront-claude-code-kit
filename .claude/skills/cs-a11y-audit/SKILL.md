# アクセシビリティ監査

## 1. 範囲を決める
- 主要フローの画面(トップ、一覧、詳細、カート、チェックアウト、ログイン)と、今回変更した画面

## 2. 機械チェック
- axe や pa11y などの自動検査を実行し、結果を保存する
- 自動検査で見つかるのは一部。合格でも終わりにしない

## 3. 手動チェック(各画面)
- [ ] キーボードだけで全操作ができる。フォーカスが見える。フォーカス順が自然
- [ ] 画像に代替テキスト。装飾画像は空の alt
- [ ] 見出しの階層が正しい(h1 が 1 つ、飛ばしていない)
- [ ] フォームにラベル。エラーが文字で分かり、どの項目か示される
- [ ] 色だけで情報を伝えていない。コントラスト比 4.5:1 以上(本文)
- [ ] 動的に変わる領域(カート数、エラー)がスクリーンリーダーに通知される(aria-live)
- [ ] 文言は翻訳キーで、言語属性が正しい

## 4. 報告の形
- 重要度 / 画面と要素 / WCAG の達成基準番号 / 再現手順 / 直し方
- 標準コンポーネントの問題か、自作の問題かを分ける(標準なら更新で直る可能性)

## 5. やらないこと
- コードは変えない。直し方の提案までにとどめる
