# SLO の定義と週次レビュー

## 1. SLO の書式(1 行 1 SLO)
```
対象: 商品詳細ページ(モバイル)
指標(SLI): 2.5 秒以内に LCP が完了した表示の割合
目標: 90%
計測窓: 直近 28 日
計測方法: 実ユーザー計測(RUM)
```
最初は 3〜5 本に絞る: 主要フローの成功率、商品詳細の LCP、OCC の 5xx 率、SSR の失敗率、注文確定の成功率。

## 2. 週次レビューの進め方(30 分)
1. 各 SLO の達成状況とエラーバジェットの残り
2. バジェットを大きく消費した出来事(リリース、障害、外部要因)
3. 対応の決定: 消費が速いなら「機能リリースより信頼性改善を優先」。余裕があるならそのまま
4. アラートの見直し: 鳴ったが動かなかったアラートは閾値を変えるか消す

## 3. 記録
- 日付、各 SLO の値、決めたこと、担当、期限

## 4. 注意
- SSR の Pod は Cloud Portal で手動でレプリカ数を変えられない前提で、キャッシュと CDN を含めて考える
- 数字の無い議論はしない。計測できていない SLO は「計測の整備」を最初のタスクにする
