# 設計判断の記録(ADR)

置き場所: `docs/adr/NNNN-短い題名.md`。番号は通し番号。

## 書式
```
# NNNN. <決定の題名>
日付: YYYY-MM-DD
状態: 提案 / 承認 / 置き換え(→ NNNN) / 廃止

## 背景
何を決める必要があるか。制約(期限、Public Cloud の制約、既存資産)。

## 選択肢
1. <案 A>: 利点 / 欠点 / コスト
2. <案 B>: ...
3. 何もしない

## 決定
<選んだ案>。理由を 3 点以内で。

## 根拠
公式ドキュメントの記述(ページ)、計測値、または「一般的な慣行」と明示。

## 影響
変わるもの(コード、運用、他チーム)。戻すときの手順。

## 未決事項
後で決めること、確認待ちのこと。
```

## チェック
- [ ] 「選択肢」に「何もしない」を含めた
- [ ] 決定に根拠がある。根拠が無い部分は「一般的な慣行」と書いた
- [ ] 影響に「戻し方」がある
- [ ] 古い決定を置き換えたときは、両方の状態欄を更新した

## よくある決定の題名
- CMS で持つかコードで持つか(機能名)
- SSR の対象ページ
- 機能ライブラリの採否(名前)
- OCC の拡張か外部 API か(データ名)
- Next.js など別フロントの併用
