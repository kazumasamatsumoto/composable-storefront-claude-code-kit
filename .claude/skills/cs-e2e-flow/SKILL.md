# 主要フローの E2E テスト

## 1. 対象フロー(優先順)
1. 匿名で検索 → 商品詳細 → カートに追加 → カート表示
2. ログイン → 配送先 → 配送方法 → 支払い(モック)→ 注文確定 → 注文確認
3. 注文履歴の参照
4. 境界: 在庫 0 の商品、無効なクーポン、セッション切れ

## 2. 設計
- 受入条件の ID をテスト名に残す(例: `CS-123-AC1`)
- 画面要素は安定した属性(`data-testid` など)で選ぶ。文言で選ばない(翻訳で変わる)
- テストデータは専用の商品・ユーザーを用意し、個人情報は架空にする
- 決済は既定でモック(SOP)。本番の決済業者には接続しない

## 3. バックエンド無しで回す
- MSW のハンドラで OCC を偽装し、実 OCC の応答を保存したものを返す
- 実 OCC で回す回帰と、モックで回す高速な回帰を分ける

## 4. 安定化
- 待ち時間の固定(sleep)ではなく、要素や応答の到着を待つ
- 不安定なテストはリトライで隠さず、原因(競合、時刻依存)を直す

## 5. 報告
- 要件 ID → テスト ID → ファイル名の表、実行結果、未カバーの受入条件
